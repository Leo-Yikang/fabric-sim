monitor 模块

📊 monitor — 指标采集与日志

阶段四：从 FCT 到丢包归因，再到运行剖面，多维可观测性

核心指标

  • FCT：Flow Completion Time，P50/P95/P99/Max
  • 丢包：总数 + 分原因 + 逐流 + 逐端口 + 逐交换机
  • ECN：标记总数，反映拥塞程度
  • 链路利用率：基于 link_bytes_sent / (bw × time)
  • 队列深度：交换机端口历史最大排队字节
  • 主机侧：固定开销 / DMA 时间 / 排队等待

模块结构

src/monitor/mod.rs ├── FlowFct # 单条流完成时间 + 丢包数 ├── EventHistogram # 事件类型直方图（P1 可观测性） ├── RunProfile # 运行剖面（max pending、bust） ├── DropBreakdown # 丢包明细（分原因/逐流/逐端口） ├── HostMetrics # 主机侧硬件延迟指标 └── SimSummary # 汇总结构，支持 pretty/CSV/JSON

SimSummary：三种输出格式

终端表格（pretty_print）

┌─────────── 仿真结果 [strack] ──────────── │ 总流数 1000 │ 完成流数 1000 │ 仿真总时长 12.345 ms │ 总发送包数 52431 │ 总重传包数 123 │ ECN 标记总数 456 │ 丢包总数 12 │ FCT P50 45.231 us │ FCT P95 123.456 us │ FCT P99 234.567 us │ FCT Max 890.123 us │ 平均链路利用率 78.5% └──────────────────────────────────────────

CSV / JSON 导出

// 批量实验写入 CSV pub fn csv_header() -> &'static str { ... } pub fn to_csv_row(&self) -> String { ... } // 可视化 / 外部工具对接 pub fn to_json(&self) -> String { serde_json::to_string(self).unwrap_or("{}".to_string()) }

CSV 表头包含 20 个字段，覆盖模式、流数、时间、包数、FCT 分位值、利用率、主机指标等全部维度。

pretty_print 在 cargo run 示例时直接输出到终端；CSV/JSON 用于批量参数扫描和后续 Python/R 分析。

可观测性增强（P1）

SimRunner 在 dispatch() 中实时更新事件直方图、pending 长度、同时间戳 burst 等诊断信息。

// dispatch() 中的可观测性代码 self.event_histogram.record(&ev.kind); let pending = self.sim.pending(); if pending > self.max_pending { self.max_pending = pending; // 事件队列峰值 } if ev.time == self.last_event_time { self.same_time_count += 1; } else { self.same_time_count = 1; self.last_event_time = ev.time; } if self.same_time_count > self.max_same_time_burst { self.max_same_time_burst = self.same_time_count; // 检测事件风暴 }
max_same_time_burst 是诊断仿真稳定性的关键指标。如果该值持续增长到数万，说明模型存在"瞬时同步"问题（如所有 Timeout 在同一时刻触发），需要调整事件生成逻辑。
