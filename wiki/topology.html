模块结构

src/topology/ ├── mod.rs # Topology / HostUplink 结构 ├── leaf_spine.rs # 两层 Leaf-Spine（典型 AI 集群） ├── fat_tree.rs # k-ary 三层 Fat-Tree ├── dumbell.rs # Dumbbell（经典 CC 实验） └── multi_rail.rs # Multi-Rail Leaf-Spine

Topology 结构

pub struct Topology { pub hosts: Vec<EntityId>, // 0 .. n_hosts-1 pub switches: Vec<Switch>, // 接在 host 之后连续编号 pub links: LinkRegistry, // 全部单向链路 pub host_uplink: Vec<HostUplink>, // host → edge_switch 映射 }
EntityId 编号规则是全局约定：hosts 从 0 开始连续，switches 紧随其后。SimRunner 通过判断 target < hosts.len() 区分主机和交换机。

Leaf-Spine 拓扑

两层结构：n_leaf 个 Leaf 交换机，每个下挂 hosts_per_leaf 台主机；n_spine 个 Spine 与每个 Leaf 全互联。

构建流程

// Entity ID 分配 hosts: 0 .. n_leaf*hosts_per_leaf leaves: leaf_start .. leaf_start + n_leaf spines: spine_start .. spine_start + n_spine // 1. 主机 ↔ Leaf（双向链路） for leaf_i in 0..n_leaf { for h in 0..hosts_per_leaf { let host_id = leaf_i * hosts_per_leaf + h; // Leaf 上添加直连 host 的出端口 + 路由 leaf_sw.routing.add(host_id, port); } } // 2. Leaf ↔ Spine（全互联） for leaf_i in 0..n_leaf { for spine_j in 0..n_spine { // Leaf 上行：目的为其他 Leaf 下挂 host leaf_sw.routing.add(other_host, leaf_up_port); // Spine 下行：目的为该 Leaf 下挂 host spine_sw.routing.add(host_id, spine_down_port); } }

关键特性

  • ECMP 天然支持：Leaf 到非本地 host 有 n_spine 条等价路径
  • 非阻塞（可选）：fabric_link_bps = host_link_bps × hosts_per_leaf / 2 时为典型 oversubscription 设计
  • 确定性路由：所有路由表在 build() 时预计算完毕，仿真运行期零路由计算开销
Leaf-Spine 是 AI 集群（如 NVIDIA DGX SuperPOD）的典型拓扑，Leaf 相当于机架交换机（ToR），Spine 相当于汇聚层。

Fat-Tree（k-ary）拓扑

教科书经典拓扑，三层结构：core / agg / edge。总主机数 = k³/4。

// 三层 Entity ID 分配 hosts: 0 .. k*k*k/4 edge: edge_start .. edge_start + k*(k/2) agg: agg_start .. agg_start + k*(k/2) core: core_start .. core_start + (k/2)^2 // 路由策略（每跳两段 ECMP） // edge → 本 pod 其他 host：直接走对应 edge 端口 // edge → 外 pod host：走上行到本 pod 的 k/2 个 agg 之一（ECMP） // agg → 上行到 k/2 个 core 之一（ECMP） // core → 下行到目的 pod 的对应 agg // agg → 下行到对应 edge // edge → 下行到对应 host

构建要点

  • k 必须为偶数（前置断言）
  • 每个 edge 与同一 pod 内所有 agg 全互联
  • 每个 agg 与特定一组 core 相连（按 index 映射）
  • 路由表覆盖所有非本地 host，确保任意两主机可达

测试断言

k=4 时: hosts = 4^3/4 = 16 switches = 4pods*2edge + 4*2agg + 4core = 20 links = 16*2 + 4*(2*2)*2 + 4*2*2*2 = 96
Fat-Tree 的优势在于任意两主机间存在多条等价最短路径，天然支持 ECMP 和 STrack 的 Packet Spraying。

路由表与 HostUplink

RoutingTable

pub struct RoutingTable { table: HashMap<EntityId, Vec<PortId>>, } pub fn add(&mut self, dst: EntityId, port: PortId) { self.table.entry(dst).or_default().push(port); } pub fn ports_for(&self, dst: EntityId) -> Option<&[PortId]> { self.table.get(&dst).map(|v| v.as_slice()) }

ECMP 体现在：同一 dst 可对应多个 port。Switch::ingress 用 hash_key % ports.len() 选择。

HostUplink

pub struct HostUplink { pub host: EntityId, pub edge_switch: EntityId, pub link_to_switch: u32, // host → switch 的链路 ID pub link_to_host: u32, // switch → host 的链路 ID }

SimRunner 通过 host_uplink 查询每个 host 应该连接到哪个 edge switch、走哪条链路。支持 Multi-Rail（一个 host 多个 NIC）。

Multi-Rail 拓扑扩展了标准 Leaf-Spine，允许每个 host 通过多个 NIC 连接多个 Leaf，实现主机级链路聚合。
