🔌 nic — 可插拔协议栈

阶段三核心：Protocol trait 抽象 + STrack / TCP / RDMA 多协议实现

设计目标

  • 统一抽象：所有协议实现同一 Protocol trait，SimRunner 零修改切换
  • STrack 核心：Packet Spraying 多路径 + 先切路再降窗 + SACK Bitmap
  • 基线对比：SimpleTcp 提供 ECMP 单路径 + 累计 ACK 的经典行为
  • RDMA 兼容：QP 状态机、PSN、消息边界，兼容 InfiniBand/RoCEv2 语义
trait 方法不返回 Result，内部不变量违反使用 expect() 即时 panic — 研究模拟器，非生产服务。

Protocol trait 接口

SimRunner 通过这 10+ 个方法与协议栈交互，涵盖流生命周期、数据收发、统计、RTO、RDMA 扩展。

pub trait Protocol { fn start_flow(&mut self, flow_id: FlowId, dst: EntityId, total_bytes: u64, now: u64); fn on_tx_tick(&mut self, now: u64) -> Vec<Packet>; fn on_rx_data(&mut self, pkt: &Packet, now: u64) -> Vec<Packet>; fn on_tx_control(&mut self, pkt: &Packet, now: u64); fn all_flows_done(&self) -> bool; fn take_finished_flows(&mut self) -> Vec<(FlowId, u64)>; fn stats(&self) -> ProtocolStats; fn has_pending_work(&self) -> bool; fn next_rto_deadline(&self) -> Option<u64>; fn next_tx_time(&self) -> Option<u64> { None } // P3 pacing-aware // RDMA 扩展（默认 no-op） fn post_send(&mut self, qpn: Qpn, bytes: u64, now: u64) {} fn post_write(&mut self, qpn: Qpn, bytes: u64, now: u64) {} fn qp_state(&self, qpn: Qpn) -> Option<QpState> { None } fn update_send_time(&mut self, flow_id: FlowId, seq: SeqNum, nic_depart_time: u64) {} }
update_send_time 是 P3 关键优化：SimRunner 在注入主机内部 DMA 延迟后，用真实 NIC 出主机时间覆盖协议层记录的 send_times，确保 RTO 从包真正离开主机开始计时。

STrack 协议：发送端与路径选择

STrack 支持两种模式：Ecmp（单路径流哈希 + 直接降窗）和 STrack（Spraying + 黑名单 + SACK）。

PathState 与路径选择

pub struct PathState { path_id: u8, blacklisted_until: u64, // 黑名单截止时间 ecn_recent: u32, // 最近 ECN 计数 } fn pick_path(&mut self, now: u64) -> Option<u8> { match self.mode { STrackMode::Ecmp => Some(0), STrackMode::Strack => { for _ in 0..n { let idx = self.paths_rr_cursor; self.paths_rr_cursor = (idx + 1) % n; if self.paths[idx as usize].is_available(now) { return Some(idx); } } Some(0) // 全黑则回退到路径 0 } } }

try_send 核心逻辑

// 1. 检查 RTO 超时 → 加入重传队列 for (seq, send_t) in &f.send_times { if now - send_t >= self.rto_ns && !retx.contains(seq) { timeout_seqs.push(*seq); } } // 2. 先重传（预算不超过 cwnd） while retx_budget > 0 && !retx.is_empty() { let seq = retx.remove(0); let path = self.pick_path(now)?; pkt.routing_tag = path + 1; to_send.push(pkt); } // 3. 再发新包（受 cwnd 和 in_flight 限制） while new_inflight < cwnd && next_seq < total { let path = self.pick_path(now)?; pkt.routing_tag = path.saturating_add(1); to_send.push(pkt); new_inflight += 1; }
发送顺序：超时重传 > 显式重传（NACK） > 新数据。每条包都通过 pick_path 动态选路。

STrack 接收端：SACK Bitmap 与 NACK

接收端维护 64-bit bitmap（received_bits），实现选择性确认，精确触发缺失包重传。

// 收到 Data 包时的处理逻辑 if seq < next { // 重复包 self.rx_stats.duplicates += 1; } else if seq == next { // 按序到达 flow.next_expected += 1; flow.received_bits >>= 1; // 右移，检查已缓存的后续包 while flow.received_bits & 1 == 1 { flow.next_expected += 1; flow.received_bits >>= 1; } } else { // 乱序包：记录到 bitmap let offset = (seq - next) as u32; if offset < 64 { let bit = 1u64 << offset; if flow.received_bits & bit == 0 { flow.received_bits |= bit; nack_needed = true; // 新乱序包 → 发送 NACK } } }

ACK Payload 编码

let mut ack_payload = Vec::with_capacity(12); ack_payload.extend_from_slice(&flow.next_expected.to_le_bytes()); // 4 bytes ack_payload.extend_from_slice(&flow.received_bits.to_le_bytes()); // 8 bytes

ACK 同时携带累计确认号和 64-bit SACK bitmap，发送端解析后可精确重传缺失片段。

on_nack 解析与重传

let base = u32::from_le_bytes([...]); // next_expected let bits = u64::from_le_bytes([...]); // received_bits for i in 0..64 { let s = base + i; if s >= nack.seq { break; } let received = (bits >> i) & 1 == 1; if !received && !flow.retransmit_queue.contains(&s) { flow.retransmit_queue.push(s); } }

STrack 拥塞控制：先切路再降窗

这是 STrack 与 ECMP 的核心差异：遇到 ECN 时不立即降窗，而是先把当前路径加入黑名单；只有当所有路径都不可用时才降低 cwnd。

fn on_ack(&mut self, ack: &Packet, now: u64) { if ack.ecn { match self.mode { STrackMode::Strack => { // 1. 将收到 ECN 的路径加入黑名单 50us let path = (ack.id as u8) % self.paths.len() as u8; self.paths[path as usize].blacklisted_until = now + self.blacklist_duration_ns; // 50_000 ns // 2. 仅当所有路径都不可用时才降窗 let avail = self.paths.iter().filter(|p| p.is_available(now)).count(); if avail == 0 { flow.cwnd = (flow.cwnd / 2).max(self.min_cwnd); } } STrackMode::Ecmp => { // 传统行为：直接降窗 flow.cwnd = (flow.cwnd / 2).max(self.min_cwnd); } } } else { // 正常 ACK：线性增窗（简化的 AIMD） flow.cwnd = (flow.cwnd + 1).min(self.max_cwnd); } }
blacklist_duration_ns = 50us，远小于 RTO（100us），允许协议快速尝试其他路径而非保守降速。这是 STrack 在 incast 场景下表现优于 ECMP 的关键。

SimpleTcp：基线协议实现

验证 Protocol trait 通用性的基线实现，包含完整的 TCP 经典机制。

核心机制

  • 单路径：无 Packet Spraying，无路径黑名单
  • 累计 ACK：无 NACK，无 SACK Bitmap
  • 慢启动 + 拥塞避免：标准 AIMD
  • 快速重传：3 个重复 ACK 触发
  • RTO 超时重传：100us 固定超时
  • ECN 响应：收到 ECN 标记 ACK 时乘性降窗

快速重传代码

if acked == flow.un_acked_base { flow.dup_ack_count += 1; if flow.dup_ack_count == 3 { // 第 3 个重复 ACK：快速重传 flow.ssthresh = (flow.cwnd/2).max(min_cwnd); flow.cwnd = flow.ssthresh + 3; flow.retransmit_queue.push(flow.un_acked_base); } else if flow.dup_ack_count > 3 { flow.cwnd = (flow.cwnd + 1).min(max_cwnd); } }
慢启动阶段 cwnd 指数增长，超过 ssthresh 后进入线性增长的拥塞避免阶段。RTO 后 ssthresh=cwnd/2, cwnd=init_cwnd。
