training 模块

🧠 training — 训练 Workload 抽象

P2 扩展：将分布式训练中的集合通信展开为底层 FlowDesc，支持 Ring / Tree / RS+AG 算法

模块文件

src/training/ ├── mod.rs # TrainingJob / Iteration / CollectiveOp / Metrics └── dag.rs # TrainingDag / DagNode / PhaseOverlap

核心概念

  • TrainingJob：一次完整训练，含多个 Iteration
  • Iteration：forward + backward + collectives 序列
  • CollectiveOp：AllReduce / ReduceScatter / AllGather / AllToAll
  • CollectiveAlgorithm：Ring / ReduceScatterThenAllGather / Tree

ChunkConfig：细粒度控制

pub struct ChunkConfig { pub chunk_size_bytes: u64, // 0 = 不切分 pub num_channels: u32, // 类似 NCCL channel pub pipeline_depth: u32, // >1 时 send/recv 重叠 }

通过调整 chunk_size、channel 数和 pipeline 深度，可以模拟 NCCL 风格的带宽优化策略。

当前为静态展开：collective 的 flow 开始时间基于逻辑计划，而非前一个 collective 的真实完成时间。后续可扩展为动态调度。

CollectiveOp 展开为 FlowDesc

每种算法生成特定的流模式，包含 chunking、channel、pipeline 的完整语义。

Ring AllReduce

// 2*(N-1) 步，每步每个节点向下一节点发送一个 chunk phase_steps = [n-1, n-1] // Scatter-Reduce + AllGather for step in 0..steps { for chunk_idx in 0..chunks { let wave = chunk_idx / channels; let start = base + (step_offset+step+wave) * spacing; for i in 0..n { let src = nodes[i]; let dst = nodes[(i+1) % n]; flows.push(FlowDesc{ flow_id: fid, src, dst, bytes, start_time_ns: start }); fid += 1; } } }

step_spacing_ns = 1_000 / pipeline_depth，pipeline 越深，时间间隔越短。

Tree AllReduce（Binary）

// Reduce 阶段：子节点 → 父节点 stride = 1; while stride < n { for i in (0..n).step_by(stride*2) { let child = nodes[(i+stride) % n]; let parent = nodes[i]; flows.push(FlowDesc{ src: child, dst: parent, ... }); } stride *= 2; } // Broadcast 阶段：父节点 → 子节点（反向） stride = n / 2; while stride >= 1 { ... stride /= 2; }

Tree 算法 flow 数 = 2×(N-1)，远低于 Ring 的 2×(N-1)×N（未切分时），但受限于树的深度和扇出。

TrainingJob 与 Metrics

Job 展开流程

let job = TrainingJob { name: "gpt3_small".to_string(), nodes: (0..8).collect(), iterations: vec![Iteration { iter_id: 0, compute_delay_ns: 100_000, // 100us 计算 collectives: vec![CollectiveOp { kind: CollectiveKind::AllReduce, algorithm: CollectiveAlgorithm::Ring, message_bytes: 1024 * 1024 * 1024, // 1GB chunk_config: ChunkConfig::default(), nodes: (0..8).collect(), }], }], }; let plan = job.plan(); runner.inject_training_job(&job); runner.run(max_time);

TrainingMetrics 输出

┌─────────── Training 指标 [gpt3_small] ──────────── │ 总迭代数 10 │ 完成迭代数 10 │ Iteration Time 平均 2.345 ms │ Iteration Time 最小 2.100 ms │ Iteration Time 最大 2.890 ms │ Collective 0 2.345 ms planned=2.000 ms done=true iter=0 allreduce-ring └──────────────────────────────────────────

Metrics 对比 planned vs actual 完成时间，帮助识别网络瓶颈是否拖慢训练。

compute_delay_ns 在每个 iteration 的 collective 序列前插入，模拟 forward+backward 的 GPU 计算时间。

测试覆盖

Collective 测试

  • Ring AllReduce flow 数 = 2×(N-1)×N（无 chunking）
  • RS+AG flow 数与 Ring 相同（两阶段各 N-1 步）
  • Tree flow 数 = 2×(N-1)（binary tree）
  • chunk_size 被尊重：所有 flow 的 bytes 等于 chunk_size
  • 显式 chunking 增加 flow 数：steps × N × chunks_per_edge
  • channel 重叠：同一 wave 内多个 channel 同时启动
  • pipeline 缩短计划结束时间

Job 级测试

  • TrainingJob.generate() 产生非空 flow 列表
  • collective boundaries 正确覆盖全部 flow_id
  • compute_delay 推动 iteration 开始时间后移
  • 多 iteration、多 collective 边界正确
Training 模块的测试不依赖 SimRunner，仅验证 collective 展开逻辑的正确性（flow 数量、顺序、大小、时间）。
