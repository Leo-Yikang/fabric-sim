sim_runner 模块

🚀 sim_runner — 端到端仿真主循环

集中式事件分发 orchestrator：连接 DES 引擎、拓扑、协议栈与流量

模块文件

src/sim_runner/ ├── mod.rs # SimRunner 结构体、初始化、事件分发、统计汇总 ├── host.rs # 主机侧：TxTick 驱动发送、PacketArrive 处理收包 └── switch.rs # 交换机侧：ingress 路由入队、egress 出队转发

核心设计

  • 不使用 Simulator::register_handler（受 borrow checker 限制）
  • SimRunner 直接读写 protocols / topo.switches / packet_buf
  • 所有事件处理完成后统一 schedule 新事件

事件流全景

FlowStart → Protocol.start_flow() ↓ TxTick → Protocol.on_tx_tick() → 包入 packet_buf ↓ PacketDepart(链路) → 序列化+传播延迟 ↓ PacketArrive@Switch → Switch.ingress() → 入队 ↓ PacketDepart@Port → 出队 → 下一跳 ↓ PacketArrive@Host → Data: on_rx_data() → ACK/NACK → Control: on_tx_control()
全局 Packet ID 由 SimRunner 的 PacketSlab 统一分配，每个 TxNic 局部 packet_id 会被重写为全局唯一值。

SimRunner 核心数据结构

SimRunner 是仿真的"中央大脑"，持有所有跨组件需要共享的状态。

pub struct SimRunner { pub sim: Simulator, pub topo: Topology, pub protocols: Vec<Box<dyn Protocol>>, // 每个 host 一个协议栈 pub link_busy_until: Vec<u64>, // 链路串行化：下一个空闲时刻 packet_buf: PacketSlab, // 轻量 Slab allocator pub fcts: Vec<FlowFct>, // 每条流的完成时间记录 pub link_bytes_sent: Vec<u64>, // 链路累计字节（用于利用率） pub sampler: TimeSeriesSampler, // 3D 可视化时序采样 pub host_delays: HostDelayConfig, // 主机内部硬件延迟 pub host_tx_busy_until: Vec<u64>, // 主机 DMA 引擎串行化 switch_index: Vec<usize>, // switch EntityId → Vec 索引映射 next_trace_id: u64, // 全局单调递增追踪 ID pending_timeout_deadline: Vec<u64>, // 每个 host 的待处理 Timeout }
switch_index 用 Dense array 做 O(1) 映射：EntityId 可能不连续（如 host 后接 switch），但最大 ID 通常不大，Vec 索引比 HashMap 快且省内存。

PacketSlab：轻量包分配器

Event 只携带 packet_id，实际 Packet 存在 SimRunner 的 slab 中。相比 HashMap<u64, Packet>，Slab 更缓存友好。

实现

struct PacketSlab { slots: Vec<Option<Packet>>, free: Vec<u64>, // 回收的索引复用 } fn insert(&mut self, mut pkt: Packet) -> u64 { let id = if let Some(id) = self.free.pop() { self.slots[id as usize] = Some(pkt); id } else { let id = self.slots.len() as u64; self.slots.push(Some(pkt)); id }; self.slots[id as usize].as_mut().unwrap().id = id; id } fn remove(&mut self, id: u64) -> Option<Packet> { let val = self.slots[id as usize].take(); if val.is_some() { self.free.push(id); } val }

为什么不用 HashMap？

  • O(1) 无哈希：直接数组索引，无哈希函数开销
  • 缓存友好：Option<Packet> 连续存储，预取效率高
  • 自动复用：free 列表管理回收索引，内存不无限增长
  • 确定性 ID：与全局 trace_id 分离，slab 索引用于事件间传递
trace_id 是单调递增的全局追踪 ID（用于可观测性），与 slab 索引解耦。即使同一个物理包被重新插入 slab（如转发时），trace_id 保持不变。

主机侧事件处理（host.rs）

TxTick 驱动协议栈发包，同时注入主机内部硬件延迟（DMA / doorbell / PCIe）。

// handle_tx_tick 核心片段 for mut pkt in pkts { let dma_time = self.host_delays.tx_dma_time(host, pkt.size as u64); let fixed = self.host_delays.tx_fixed_overhead(host); // DMA 开始 = max(当前时间+固定开销, DMA引擎空闲时刻) let dma_start = (now + fixed).max(self.host_tx_busy_until[host_idx]); let nic_depart_time = dma_start + dma_time; // 更新主机侧指标 self.host_total_fixed_overhead_ns += fixed; self.host_total_dma_time_ns += dma_time; self.host_total_queue_wait_ns += dma_start - (now + fixed); // 占用 DMA 引擎直到本包离开主机 self.host_tx_busy_until[host_idx] = nic_depart_time; pkt.depart_time = nic_depart_time; // 链路串行化 let start = self.link_busy_until[link_id].max(nic_depart_time); let depart_done = start + link.serialization_ns(pkt.size); let arrive = depart_done + link.prop_delay_ns; self.link_busy_until[link_id] = depart_done; }
链路模型和主机 DMA 模型都使用 "busy_until" 模式：下一个包的开始时间 = max(当前请求时间, 资源空闲时间)。这是离散事件仿真中建模串行资源的经典技巧。

交换机侧事件处理（switch.rs）

PacketArrive @ switch → ingress → 入队 → try_egress。Egress 由端口空闲状态驱动。

pub(super) fn handle_packet_arrive(...) { // 1. 从 slab 取出包 let pkt = self.packet_buf_remove(pid)?; // 2. 交换机 ingress（路由 + 判丢包 + 判 ECN + 入队） let hash_key = pkt.src ^ pkt.dst ^ pkt.flow_id; let (port_opt, dropped) = sw.ingress(pkt, hash_key, now); if dropped { return; } // 3. 尝试 egress（如果端口空闲立即发，否则调度 PacketDepart） self.try_egress(sw_idx, port, now, pid, pkt_size); }
fn try_egress(&mut self, sw_idx, port, now, ...) { if busy_until <= now { // 端口空闲：立即出队转发 let pkt = sw.dequeue(port)?; // 计算链路 serialization + prop，调度 PacketArrive 到下一跳 ... // 如果队列仍非空，调度 PacketDepart 在 depart_done 时刻重试 if still_queued && !p.egress_pending { p.egress_pending = true; sim.schedule(Event::new(depart_done, PacketDepart{...}, sw_id)); } } else { // 端口忙：调度 PacketDepart 在 busy_until 时刻重试 if !p.egress_pending { p.egress_pending = true; sim.schedule(Event::new(busy_until, PacketDepart{...}, sw_id)); } } }
egress_pending 布尔标志防止同一端口堆积多个 PacketDepart 事件。队列中已有的 Pending 事件会在处理时自动连续驱动后续包。

调度优化：取消冗余 Timeout

当 ACK 提前到达并触发 TxTick 时，之前调度的 RTO Timeout 变为冗余。SimRunner 通过两层机制清理。

逻辑取消

// schedule_host_next_action 中 if has_pending_work { self.pending_timeout_deadline[host] = u64::MAX; self.cancel_host_timeouts(host); // 调度 TxTick... } // dispatch 中处理 Timeout 事件时 EventKind::Timeout{..} => { if ev.time != pending_timeout_deadline[host] { return; // 已被逻辑取消，忽略 } ... }

物理删除

fn cancel_host_timeouts(&mut self, host: EntityId) -> usize { self.sim.cancel_where(|ev| ev.target == host && matches!(ev.kind, Timeout{..}) ) }

cancel_where 内部 O(n) 扫描事件队列并重建 4-ary heap，适合批量清理。

两层机制结合：逻辑取消保证即使物理删除滞后，过时 Timeout 也不会误触发；物理删除避免事件队列无限增长。

summarize()：仿真结果汇总

仿真结束后聚合 FCT、丢包、链路利用率、主机侧指标、Training 指标等多维数据。

Training 指标（如果有） self.compute_training_metrics(); summary }
