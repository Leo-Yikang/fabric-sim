core 模块

🎯 core — 离散事件仿真引擎

阶段一核心成果：与网络概念完全解耦的通用 DES 引擎

模块职责

  • 事件定义统一的事件类型 Event 与种类 EventKind
  • 优先队列自定义 4-ary heap，百万级事件下高吞吐
  • 时钟驱动全局仿真时钟 SimTime = u64（纳秒）
  • 调度器Simulator 负责事件排序、派发、生命周期管理
引擎本身不知道什么是"包"或"交换机"，只认时间戳和 target ID — 这是解耦的关键。

文件结构

src/core/ ├── mod.rs # 模块入口，导出 Event/EventQueue/Simulator ├── event.rs # Event + EventKind + FIFO 稳定性排序 ├── queue.rs # EventQueue（4-ary heap 实现） └── simulator.rs # Simulator 主循环

事件类型与 FIFO 稳定性

所有网络语义被编码为结构化枚举变体，避免字符串解析开销。

pub enum EventKind { PacketArrive { packet_id: u64, src: EntityId }, PacketDepart { packet_id: u64, dst: EntityId, port: u8 }, Timeout { timer_id: u64 }, FlowStart { flow_id: u32, src: EntityId, dst: EntityId, bytes: u64 }, TxTick { host: EntityId }, Stop, Custom(String), # 仅用于单元测试/示例 }

全局原子序号保证 FIFO

static EVENT_SEQ: AtomicU64 = AtomicU64::new(0); impl Ord for Event { fn cmp(&self, other: &Self) -> Ordering { // 反向比较：BinaryHeap 是最大堆，反向后变成最小堆 other.time.cmp(&self.time) .then_with(|| other.seq.cmp(&self.seq)) } }
当两个事件时间戳相同时，按插入顺序（seq）弹出，保证仿真确定性 — 这对可复现研究至关重要。

EventQueue：4-ary Heap 优化

标准库 BinaryHeap 是二叉堆；我们改用四叉堆（4-ary heap），树高减半，sift 操作缓存友好。

核心操作

pub struct EventQueue { heap: Vec<Event>, } // push: O(log₄ N) pub fn push(&mut self, ev: Event) { self.heap.push(ev); self.sift_up(self.heap.len() - 1); } // pop: O(log₄ N) pub fn pop(&mut self) -> Option<Event> { // 首尾交换 + 下沉 ... }

sift_down 在四叉堆中的差异

fn sift_down(&mut self, mut idx: usize) { let len = self.heap.len(); loop { let first_child = idx * 4 + 1; if first_child >= len { break; } let last_child = (first_child + 3).min(len - 1); let mut min = idx; for child in first_child..=last_child { if Self::ev_less(&self.heap[child], &self.heap[min]) { min = child; } } if min == idx { break; } self.heap.swap(idx, min); idx = min; } }
每个节点最多 4 个子节点，sift 时比较范围从 2 个扩大到 4 个，但树高从 log₂N 降到 log₄N，整体内存访问次数更少。

Simulator 主循环

提供 step、run_until、run 三级驱动接口。内置 handler 注册机制（第一阶段使用），后续被 SimRunner 的集中式分发取代。

pub struct Simulator { clock: SimTime, // 当前仿真时钟（ns） queue: EventQueue, // 4-ary min-heap handlers: HashMap<EntityId, Handler>, processed: u64, // 已处理事件总数 stopped: bool, } pub fn step(&mut self) -> Option<SimTime> { let ev = self.queue.pop()?; // 取出最早事件 self.clock = ev.time; // 推进时钟 self.processed += 1; let new_events = if let Some(h) = self.handlers.get_mut(&ev.target) { h(&ev, self.clock) // handler 返回新事件 } else { Vec::new() }; for nev in new_events { self.queue.push(nev); // 统一压入队列 } Some(self.clock) }
实际网络仿真中，我们没有使用 handler 回调（受 borrow checker 限制），而是采用 SimRunner 集中式分发：Simulator 只负责排序，业务逻辑在外层处理。

关键设计要点与性能数据

设计决策

  • 整数运算：全部时间计算使用 u64 纳秒，避免浮点误差
  • 软提升：落后时钟的事件被提升到当前时钟，而非 panic
  • 批量取消：cancel_where O(n) 扫描 + 重建堆，适合 Timeout 清理
  • 预分配：new_with_capacity 减少 Vec 扩容，提升 5–10%

实测性能

Debug 模式: ~2 M events/sec Release模式: ~20 M events/sec 集成测试阈值: > 0.5 M events/sec （百万级事件场景）
release 模式下 4-ary heap 的缓存友好性得以体现，相比标准库 BinaryHeap 有约 5–15% 的额外提升。
